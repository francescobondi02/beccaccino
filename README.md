# Becca AI — Reinforcement Learning for Beccaccino

Self-play training system for the Italian card game Beccaccino. The strongest
recipe is a **behavioral-cloning warm-start** (imitate the heuristic) followed by
**PPO self-play** on a **V4 transformer** card encoder, with per-seat GAE, an
opponent diversity pool (with permanent anchors), an optional centralized (CTDE)
critic, curriculum learning, and wandb tracking. Four network families ship
(V1 MLP → V2 residual → V3 factorized head → V4 transformer). The two-phase
BC→PPO setup lives in `scripts/bc_then_rl.py`; all PPO lifecycle behavior lives
in `training/engine.py`, with `scripts/train.py` as the pure-PPO CLI adapter.

## A0-A10 Refactor Status

The 2026-08-24 correctness pass changed the training contract:

- **A0 — deal streams and CPU resume:** vector worker `i`, game `g`, uses
  `base_seed + i + g * num_workers`, so workers do not replay one another's
  deals. Checkpoints now preserve every worker's live game, pending rewards,
  seed-stream position, current observation, unfinished rollout carry,
  return-normalizer chains, and global RNG. A CPU regression test proves that
  uninterrupted and resumed rollouts produce identical transitions and deal
  fingerprints across the boundary.
- **A1 — deferred rewards:** rewards that accumulated since a seat last acted
  are retro-credited to that seat's previous transition. The action currently
  being executed receives only reward generated by that action.
- **A2 — public round state:** the actor observation is now 470 floats and the
  CTDE full state is 590. The unchanged 462-float prefix is followed by team
  captured raw points (2), team trick counts (2), and a viewer-relative caller
  one-hot (4).
- **A3 — bounded signal history:** the current actor observation is 518 floats
  and the CTDE full state is 638. Four newest-first declaration records retain
  declarer, signal, led suit, and trick timing, preserving order and repeated
  declarations without an unbounded round history.
- **A4 — card-conditioned signals:** current V4 policies predict three signal
  deltas from each candidate card token while keeping the no-signal card logit
  unchanged. Older V4 checkpoints reconstruct their original global signal
  head for inference, but cannot resume current training.
- **A5 — held-out champion selection:** `best.pt` remains a monitoring candidate,
  not a champion. Promotion directly matches a candidate against the incumbent
  on at least 1,000 fresh mirrored deals and writes checkpoint hashes, every
  paired outcome, confidence intervals, and public-state slices to `score.jsonl`.
- **A6 — PIMC correctness:** determinized hands never relax proven voids;
  sampled worlds are weighted by public signal consistency; rollout leaves use
  cumulative match utility and exact threshold/caller tie-break outcomes; and
  equivalent signal branches collapse to one card search before the policy
  chooses the signal variant.
- **A7 — measurable near-perfect protocol:** `NearPerfect-v1` is a fail-closed
  evidence manifest spanning three training seeds, a multi-class opponent
  panel, repaired-PIMC gain, deployment latency, three approximate best
  responses, and a frozen expert-state corpus.
- **A8 — durable, attributable checkpoints:** format-3 checkpoints stamp the
  source commit/tree/dirty hash and the resolved Python, platform, dependency,
  Torch, CUDA, and cuDNN runtime. Saves fsync a same-directory temporary file
  before atomic replacement, write a SHA-256 sidecar, and retain a verified
  `.prev.pt` generation for automatic corruption fallback.
- **A9 — fresh long-run identity:** historical `runD` cannot launch; the
  `rund2` preset starts `runD2` from regenerated BC data under A0-A8.
- **A10 — one PPO engine:** pure PPO and BC→PPO now share rollout, schedules,
  evaluation, curriculum, checkpoint, deadline, and exact-resume behavior in
  `training/engine.py`. The drifted `scripts/train_and_plot.py` loop was removed.

Legacy 462-feature and A2 470-feature checkpoints remain loadable for inference
because their input width is inferred or read from checkpoint metadata. They
cannot resume 518-feature training. The architecture changes are implemented
and parity-tested, but their fixed-budget three-seed ablations have not been
run; better held-out value fit or paired playing strength remains an unproven
promotion gate. A4's signal-response and card-strength promotion experiments
also remain unrun. Repaired PIMC has not yet run its promotion experiment: it
must beat the bare champion by at least two points with a positive paired lower
bound, with deployment CPU p95 below one second and every move below five.
No current artifact supports the scoped `NearPerfect-v1` claim.

## Training Commands

### Recommended: BC warm-start → PPO self-play (`scripts/bc_then_rl.py`)

The strongest recipe. Behavioral-cloning the heuristic first gives PPO a large
head start. Add `--network-version 4` for the transformer. See
`scripts/kaggle_setup.md` for the full GPU recipe, or drive Kaggle runs from the
CLI with `scripts/kaggle_run.py` (see "Kaggle GPU runs" below).

```bash
python -m scripts.bc_then_rl \
  --network-version 4 --d-model 128 --nhead 4 --layers 3 --dim-feedforward 256 \
  --bc-games 3000 --bc-epochs 5 --total-rl-steps 5000000 \
  --num-envs 32 --wp-mix 5,41 --eval-win-points 41 --device cuda
```

`--wp-mix 5,41` balances both game lengths across learner teams inside each
rollout. Use `--win-points N` instead when intentionally training one length;
the two options are mutually exclusive.

### Pure PPO trainer (`training/trainer.py`)

Supports `--network-version {1,2,3,4}`, `--resume`, `--max-hours` (graceful stop
for Kaggle's 12h cap), a global `--seed`, and (via config) a BC-anchor opponent
and a centralized CTDE critic.

### Resume from Checkpoint

```bash
python -m scripts.train \
  --resume checkpoints/ckpt_000500.pt \
  --steps 50000000 \
  --device mps
```

Exact continuation is guaranteed by regression test on CPU checkpoints written
with the current format-3 `rollout_state`. Resume verifies the `.sha256` sidecar
and automatically falls back to the verified `.prev.pt` generation before
restoring RNG after constructors that consume it. Sidecar-less format-2
checkpoints, checkpoints without `rollout_state`, and 462/470-feature artifacts
remain loadable for inference or warm starts but cannot resume current training.
Start a new 518-feature run from regenerated BC data. Exact GPU bit
reproducibility is not claimed.

Key metrics to watch:
- `eval/vs_random` — win rate against random baseline (primary success metric)
- `train/entropy` — should decrease slowly (exploration → exploitation)
- `train/explained_variance` — should trend toward 1.0 (value function accuracy)
- `train/approx_kl` — should stay below 0.02 (policy stability)
- `perf/sps` — steps per second (throughput)

## Evaluation

```python
import torch
from training.network import create_network
from evaluation.arena import evaluate_against_random, play_match, NeuralAgent, RandomAgent

# Load trained model
net = create_network(version=2, hidden_size=512, num_layers=3)
ckpt = torch.load("checkpoints/final.pt", weights_only=False)
net.load_state_dict(ckpt["model"])

# Win rate vs random (400 games, balanced sides)
wr = evaluate_against_random(net, num_games=400)
print(f"Win rate: {wr:.1%}")

# Model vs model comparison
net_old = create_network(version=2, hidden_size=512, num_layers=3)
ckpt_old = torch.load("checkpoints/ckpt_000100.pt", weights_only=False)
net_old.load_state_dict(ckpt_old["model"])

result = play_match(NeuralAgent(net), NeuralAgent(net_old), num_games=200)
print(f"New wins: {result.team0_wins}, Old wins: {result.team1_wins}")
```

## Cross-checkpoint Elo ladder

vs-random saturates near 95%, so use a round-robin Elo ladder on a frozen deal
block to rank strong checkpoints against each other:

```bash
python -m scripts.elo_ladder checkpoints/a.pt checkpoints/b.pt --num-games 100
```

For the final shipping decision, directly compare a candidate with the current
champion on a fresh, predeclared seed block:

```bash
python -m scripts.score_checkpoints \
  --candidate checkpoints/best.pt \
  --incumbent checkpoints/deployed.pt \
  --protocol-id "${PROTOCOL_ID}" \
  --seed-base "${FRESH_SEED_BASE}" \
  --games 1000 \
  --output "runs/${PROTOCOL_ID}/score.jsonl"
```

`--games 1000` means 1,000 deals played with both team assignments, or 2,000
games. The output path must be new, and the seed block must not have been used
to tune or select the candidate. Promotion requires the paired 95% lower bound
to exceed 50%; otherwise retain the incumbent. Positional checkpoint arguments
remain available for historical heuristic benchmarking only.

The stronger research claim is defined in
[`docs/EVALUATION_PROTOCOL.md`](docs/EVALUATION_PROTOCOL.md). Validate a
completed evidence manifest with:

```bash
python -m scripts.check_near_perfect runs/near-perfect-v1/evidence.json
```

## Kaggle GPU runs

Drive Kaggle GPU training from the CLI (no notebook editing). Ships `ai/` as a
dataset, configures a GPU kernel, and launches a run. A `smoke` preset is free;
anything above ~1M steps requires `--confirm-cost`.

```bash
python -m scripts.kaggle_run push-code --create   # first time; else omit --create
python -m scripts.kaggle_run configure            # GPU + internet on
python -m scripts.kaggle_run launch --preset smoke
python -m scripts.kaggle_run status
python -m scripts.kaggle_run pull -p checkpoints/kaggle
```

Run D was the resumable 60M-step mixed `wp=5,41` experiment. Its artifacts and
measurements are historical, and `--preset rund` now fails closed. Run D2 uses
the corrected A0-A8 contract and a fresh identity. Keep its final target and
batch geometry unchanged across sessions:

```bash
# Session 1
python -m scripts.kaggle_run launch --preset rund2 --confirm-cost

# After each capped session
python -m scripts.kaggle_run status
python -m scripts.kaggle_run pull -p checkpoints/kaggle-rund2
python -m scripts.kaggle_run push-state \
  --from checkpoints/kaggle-rund2 --create -m "runD2 session 1"
python -m scripts.kaggle_run launch \
  --preset rund2 --resume-state --confirm-cost
```

Use `--create` only for the first state-dataset upload. The earlier real Kaggle
smoke round-trip succeeded, but a new paid run must repeat the stop/pull/push/
resume smoke with the current exact-vector-state checkpoint format. See
`docs/TRAINING_RUNBOOK.md`.

                    unified checkpoint/resume, V1–V4 networks

                    kaggle_run, benchmark
