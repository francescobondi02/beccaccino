# Frontend

React 18, Vite, TypeScript, Tailwind and shadcn/ui. The website for laptop and
desktop windows of at least 1024×600 px. Phones and tablets use the native app.

## Run

Run `make dev` from the root, then open http://localhost:8081. The `frontend`
container runs `npm run dev` with hot reload.

The browser always calls `/api` and `/socket.io/` on its own origin, so the
`authToken` cookie goes with every request. In development Vite proxies both
to `BACKEND_URL` (default `http://localhost:8000`; the container uses
`http://backend:8000`). In production Vercel forwards them to Render. No `.env`
file is needed.

## Scripts

Run them in the container, for example `docker compose exec frontend npm run lint`.

| Script | What it does |
| --- | --- |
| `npm run dev` | Vite dev server on port 8081 |
| `npm run build` | Production build into `dist/` |
| `npm run build:dev` | Build in development mode |
| `npm run preview` | Serve the production build |
| `npm run typecheck` | Type check |
| `npm run lint` | ESLint |
| `npm test` | Vitest unit tests (`src/**` and `server/**`) |

## End-to-end tests

Playwright plays real games in 4 browser contexts (`e2e/`). There is no npm
script: run `npx playwright test`. By default it starts its own backend
(`npm run dev:e2e` on `becca_test`) and frontend. Set `E2E_EXTERNAL_SERVERS=true`
to test servers you already run, and `E2E_BASE_URL` for another address.
The practice spec needs a bot service. CI runs `e2e/full-game.spec.ts` on
pushes to `main`, with `GAME_WIN_POINTS=5`.

## Structure

- `src/pages/`: one component per route: `/` lobby, `/room/:roomCode` waiting
  room, `/game/:gameRoomCode` table, `/practice`, `/profile`, `/leaderboard`.
- `src/hooks/`: REST reads (React Query), socket subscriptions and reconnects.
- `src/game/`, `src/rooms/`: pure selectors.
- `src/components/`: views. `components/ui/` is generated by shadcn/ui.
- `src/sockets/socketClient.ts`: one Socket.IO client, reconnects forever.
- `src/lib/api.ts`: typed REST helpers.
- `api/socket-proxy.ts` and `server/socketProxy.ts`: the Vercel Function that
  bridges WebSocket upgrades to Render.
- `public/images/cards/`: card images named `<value>_<suit>.png`, with the
  suit spelled `denari` (the database uses `denara`). `PlayingCard` maps it.

## Deploy

Vercel builds this folder on every push to `main`. `vercel.json` sends
`/api/*` and Socket.IO polling to `https://beccaccino-server.onrender.com`, and
WebSocket upgrades to `api/socket-proxy.ts`. That function forwards only the
`authToken` cookie and is cut after 300 s; the client reconnects.

Each build writes `dist/version.json` with a random id. Open tabs poll it and
show "Aggiornamento disponibile" with a "Ricarica" button when it changes.
